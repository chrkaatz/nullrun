# Conformance run — build 0.9.1

Date: 2026-09-10 · Spec: 0.9.1 · `nullrun.html`
Reported by playtest, seed `394LHH`: a run lost on layer 2 with firewall at 43 and untouched.

## What happened on that seed

Layer 2 offered:

| node | integrity | reach | |
|---|---|---|---|
| ICE WALL | 89 | 65 | impossible |
| CORPSEC SWEEP | 108 | 69 | impossible |
| COLD STORAGE | 58 | 71 | takeable |

ICE WALL was taken. Replayed with perfect play — breach every turn, every contact spent on
damage — the run still ends: traced on turn 8 with the construct at 18. The fight was never
close and was never losable on skill. It was arithmetic, settled the moment the node was chosen.

Firewall never dropped below 43. The player did not lose a fight; they lost a calculation.

## The defect

`damageBudget()` already existed and is used to enforce `I2`. **The build knew ICE WALL was
impossible and displayed none of it.** The offer read
`ICE WALL · COMBAT · Integrity 89 · armour 3 · PAYOUT 167¤` — every number needed for the
decision except the one that decided it.

This contradicts P3.1, "losing is always a decision the player made, never a surprise". The
spec already commits to telegraphing exact intent values a full turn before they land (FR-3);
it never applied the same honesty to choosing a node. A `gap` under M3: build and spec agreed,
both were wrong.

## Fix

FR-10 now requires each node to state its **reach** — the most damage the current roster and
breach could bring before trace ends the node, and whether that clears it. Reach is a ceiling
assuming perfect play, so *beyond reach* is a guarantee of failure while *within reach* is
only a possibility; the spec says so explicitly.

The same seed now reads:

```
ICE WALL       Integrity 89  · armour 3 · BEYOND REACH · you can bring 65 of 89
CORPSEC SWEEP  Integrity 108 · armour 1 · BEYOND REACH · you can bring 69 of 108
COLD STORAGE   Integrity 58  · armour 0 · WITHIN REACH · you can bring 71
```

## What the honesty exposed

**67% of all offers are impossible.** The fix makes the game fair, and in doing so shows the
choice is usually not a choice: two traps and one road. Previously that was invisible and
lethal; now it is visible and merely thin.

That is a real design problem and it is not fixed here. Three directions, none taken:

- raise reach so hard nodes open more often (roster growth, breach growth — §T)
- let a node be abandoned without ending the run, which needs `O11` resolved
- generate offers scaled to reach, so a layer always presents a genuine spread of difficulty

## Unchanged

`K17` still fails from 0.8.0 — trace ends 0% of runs, and the trace/clearability coupling is
untouched. The build remains unaccepted under §K.
