# Conformance run — build 0.9.3

Date: 2026-09-10 · Spec: 0.9.3 · `nullrun.html` **unchanged**

Spec-only. No game logic changed; `tools/speclint.py` was added and its findings fixed.

## The linter found three real defects on a spec declared clean one version earlier

**1. `NFR-8` had not existed since 0.4.0.** The Presentation requirement was silently renamed
`NFR-9`. Cause: the 0.4.0 FR renumber ran `replace('FR-8', 'FR-9')`, and `FR-8` is a substring
of `NFR-8`. A five-version-old corruption that survived eighteen conformance checks, four
rebuilds and every review, because nothing ever checked that requirement numbering was dense.

**2. `O` numbering had a hole at 4**, left when the resolved entries were merged in 0.9.0.

**3. `I7` was guarded by no §K check.** "Every screen has an exit" was an invariant nothing
tested. `K8` tested exits from the encounter only, and cited `I5`.

All three fixed. `K8` widened to cover every screen and cite `I5, I7`; `O` renumbered dense;
`NFR-9` restored to `NFR-8` using a word-boundary-safe substitution, which is what 0.4.0
should have used.

## What the linter checks

| check | caught this session |
|---|---|
| duplicate ids | yes — two `FR-8`s existed briefly during the 0.4.0 insert |
| dense numbering | **yes — `NFR-8`, `O4`** |
| dangling cross-references | catches ids that resolve to nothing |
| every invariant guarded by a check | **yes — `I7`** |
| word budget, read from M5 itself | yes, repeatedly |
| §T values match the build's `CONFIG` | spec/build drift, the M1 failure mode |
| version has a CHANGELOG entry | **yes — 0.9.1 had none** |
| version has a conformance record | yes |

Eighty lines, no schema, no dependencies. It reads the spec, the build and the log as text
and is regenerable, so it stays disposable under M1.

**What it cannot do.** It catches a reference that resolves to *nothing*, not one that resolves
to the *wrong* thing. When the 0.4.0 renumber left `K14` citing `FR-6`, `FR-6` still existed —
as Firewall — so the citation was valid and wrong. Only reading it caught that. Numbering gaps
are the linter's proxy for deletion; semantic drift remains a human job.

## Not adopted: a database

A SQLite index was considered. Rejected for the spec itself: the document's value under M5 is
being readable in one pass, and rows would destroy that while solving a lookup problem the
spec does not have at 19 requirements. The integrity problems above are constraint checks,
not queries, and a linter states them in one line each.

The one place structured storage would earn its keep is the conformance measurements — win
rate, encounter length, trace share, per version — which are numeric series currently trapped
in prose tables across nine files. At nine runs that is a CSV, not a database.

## Replayed against history

Run against past tagged specs, the linter reports:

| version | findings |
|---|---|
| 0.4.0 | `NFR` gap [8]; unguarded `I7` |
| 0.7.1 | `NFR` gap [8]; **`I` gap [2]**; unguarded `I7` |
| 0.9.1 | `NFR` gap [8]; `O` gap [4]; unguarded `I7` |

It catches `NFR-8` in the version that broke it, five versions before a human noticed.

More significantly, **`I gap [2]` at 0.7.1 is the deleted `I2`** — the guarantee of a takeable
node, cut in 0.5.0 along with alarm because it happened to mention alarm. That absence was
found by playtesting in 0.8.0, after a run was lost to an unwinnable layer. The linter would
have flagged the hole where an invariant used to be, one version earlier and for free.

It cannot know an invariant *should* exist. It can see that one stopped existing.
