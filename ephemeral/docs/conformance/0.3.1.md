## K15 failure — the run is unwinnable

Starting roster (VELVET, BISHOP, SPARROW, MOLE, HATCHET) total damage, spent once:

| Construct | Integrity | Armour | Roster can deal |
|---|---|---|---|
| COLD STORAGE | 34 | 0 | 29 |
| ICE WALL | 52 | 3 | 23 |
| HUNTER | 60 | 2 | 25 |
| CORPSEC SWEEP | 74 | 1 | 27 |
| ARCHON | 96 | 3 | 23 |

Contacts never return to ready within a run (I3), so this is the entire damage budget until
a node is cleared — and no node can be cleared. Greedy policy over 200 seeds: 0 wins,
0 layers cleared, median 8 turns. Recorded as `O4`.

## K15 investigation — three candidate fixes, all measured, all rejected

Policy: quietest node, largest affordable hit, heal when firewall is at or below the
telegraphed value. 200 seeds per cell, fixed collection state.

**Lower construct integrity** (run-scoped burn kept):

| integrity × | win rate | mean turns per encounter |
|---|---|---|
| 1.00 | 0% | — (nothing ever dies) |
| 0.70 | 6.5% | ~1 |
| 0.60 | 34% | 0.33 |
| 0.50 | 79% | ~0 |

Wins arrive only by making encounters end before they start: at ×0.6, **71% of encounters
are won without ever ending a turn**, and alarm rose above 0 in **0 of 200 runs**. Trace and
telegraphing are inert — a construct that never acts cannot threaten anything.

**Per-encounter burn** (roster refreshes at each node; changes I3, so a rebuild under M4):
still 0–5% wins across integrity ×0.5–0.7 and RAM 2–3. One full roster is 29 damage against
a 34-integrity softest node, so refreshing it per node does not clear the bar.

**More firewall** (40 / 60 / 80, RAM 2–3, integrity ×0.85–1.0): **0% wins in every cell.**
Firewall buys turns, and turns buy nothing.

### Conclusion

Damage per encounter is bounded by roster size, not by time. The encounter is decided
arithmetically on entry. No assignment of firewall, RAM, integrity or trace changes that,
because none of them adds damage. The design needs a renewable damage source — a free
action, or contacts that do not burn — which is a `feature` and a rebuild. Recorded as `O4`.
