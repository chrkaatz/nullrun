## What the cut removed

Alarm level, alarm intent scaling, alarm carry-over, alarm nodes and their payout bonus,
HUNTER's alarm gate, invariant I2, and the alarm chip on two screens. HUNTER is now an
ordinary construct in the offer pool. Intent values are constant, so FR-3's freeze rule
became trivial and was simplified.

Justification: alarm fired in **0% of runs in every configuration measured across builds
0.3.1, 0.4.0 and 0.4.1.** It was unreachable by construction — trace resets per node and
encounters last two to three turns, so trace never approached 100.

## K17 caught the same mistake immediately

With alarm cut and trace inheriting its role, the first measurement at the inherited
`trace per turn 6` showed **trace ending 0% of runs**, peak trace seen 45 of 100. The
replacement mechanic was as dead as the thing it replaced.

`trace per turn` raised 6 → 15 (a §T tune, an iterate). Trace now ends 42% of runs.

`traceMax` was deliberately not touched: FR-9 fixes the meter at "0 to 100", so lowering
the ceiling would have contradicted the requirement text rather than tuned against it.

## Caveat on that number

Trace was tuned against a baseline that still fails K15, so 42% is "the clock strikes",
not "the clock is correctly set". It will need retuning once viability is fixed, because
death by trace and death by firewall currently compete for the same broken runs
(42% trace, 59% firewall, 0% wins).

## K15 remains: the roster replenishment ratio

Unchanged by this work and unaffected by it. Contacts burn ~4 per node; payout replenishes
1, now competing with repair for that slot. The roster is bankrupt by layer 2.

Largest measured lever remains per-encounter burn (1.6 → 4.4 mean layers, measured on
0.4.1), which changes I3 and is a rebuild.
